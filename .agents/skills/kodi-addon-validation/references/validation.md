# Validation stages
Use the isolated Python environment: kodi-toolkit validate PATH --branch nexus. The exposed kodi_validate tool runs the same wrapper for the disposable fixture; it does not execute add-on code.
Inspect every stage and preserve raw diagnostics: syntax, manifest/packaging, mypy with version-matched Kodistubs, official addon-check process. A warning-only checker run can exit zero. A timeout, traceback, missing cache or schema failure is not a clean result. Do not silently change .tests-config.json or install dependencies.
Official checker 0.0.36 makes remote index and URL requests even with --skip-dependency-checks. Toolkit execution replays explicitly acquired local index snapshots, blocks network, and preserves unverified-URL warnings. Cache setup is explicit and separate; validation never downloads add-on dependencies. Record snapshot hashes/date and target branch. Offline coverage is not live repository submission approval.
Syntax parsing does not import Kodi modules. Type checking is useful for API signatures but not runtime semantics. Stub/target version mismatches must be reported. Declared dependencies are not resolved by downloading their packages. Packaging checks concern the resulting add-on payload, not unrelated development files in its source repository.
For contextual review use review.md. After a source repair rerun affected stages, keeping old failing output. Report exact checks, warnings, skipped stages and no-runtime-test limitation.
Sources: https://github.com/xbmc/addon-check ; https://github.com/romanvm/Kodistubs
